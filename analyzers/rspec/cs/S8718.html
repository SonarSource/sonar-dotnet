Using runtime-evaluated expressions (e.g., DateTime.UtcNow) as default values for date/time properties causes the value to be hardcoded as a static timestamp in the database schema. This affects HasDefaultValue() in Fluent API configurations and defaultValue in migration files.

Why is this an issue?

  • The Cause: These C# expressions evaluate once when the model builds or the migration runs, rather than dynamically by the database.
  • The Result: Every new record receives that exact same static timestamp instead of the actual time it was inserted.

Starting with EF Core 9, this also throws an InvalidOperationException for the PendingModelChangesWarning warning when applying migrations, because the default value expression evaluates to a new timestamp on each model build, making migrations non-deterministic.

How to fix it

Replace HasDefaultValue() with HasDefaultValueSql() in Fluent API configurations, and replace defaultValue with defaultValueSql in migration files. Use the appropriate database function for your specific database provider (e.g., GETDATE() or SYSUTCDATETIME() for SQL Server). This instructs EF Core to let the database engine generate the exact time of insertion.

Code examples

Noncompliant code example

public void Configure(EntityTypeBuilder<User> builder)
{
    builder.HasKey(x => x.UserId);
    builder.Property(x => x.CreatedOn)
        .IsRequired(true)
        .HasDefaultValue(DateTime.Now); // Noncompliant
}

Compliant solution

public void Configure(EntityTypeBuilder<User> builder)
{
    builder.HasKey(x => x.UserId);
    builder.Property(x => x.CreatedOn)
        .IsRequired(true)
        .HasDefaultValueSql("GETDATE()");
}

Noncompliant code example

migrationBuilder.AddColumn<DateTime>(
    name: "OrderDate",
    table: "Orders",
    nullable: false,
    defaultValue: DateTime.UtcNow); // Noncompliant

Compliant solution

migrationBuilder.AddColumn<DateTime>(
    name: "OrderDate",
    table: "Orders",
    nullable: false,
    defaultValueSql: "GETUTCDATE()");

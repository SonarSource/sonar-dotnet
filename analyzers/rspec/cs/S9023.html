An Include call can compile and run without error while Entity Framework Core silently drops the data it requests.

Why is this an issue?

Entity Framework Core tracks pending Include calls against the shape of the entity flowing through the query. An operation such as SelectMany that changes this shape to a different entity type drops any Include that was requested against the earlier shape. No exception is thrown and no warning is logged, so the missing data is only noticed once it turns out to be missing.

What is the potential impact?

Code that expects a navigation to be loaded still compiles and runs, but the property is null or empty at runtime. The resulting bug — a NullReferenceException, or silently incomplete data shown to a user — surfaces far from the query that caused it.

How to fix it

Move the Include after the operation that changes the shape, anchored on the new entity type. This requires a navigation back to the original type; if the target entity does not expose one, add it, or restructure the query so the Include runs before the shape-changing operation.

Code examples

Noncompliant code example

var posts = await context.Blogs
    .Include(b => b.Owner) // Noncompliant: dropped once SelectMany reshapes the query to Post
    .SelectMany(b => b.Posts)
    .ToListAsync();

Compliant solution

var posts = await context.Blogs
    .SelectMany(b => b.Posts)
    .Include(p => p.Blog).ThenInclude(b => b.Owner)
    .ToListAsync();
